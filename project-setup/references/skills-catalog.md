# Skills catalog

Library and domain skills worth installing per stack. Workflow skills
(`architect`, `review`, `recover`, `remember`, `imprint`, `add-library-skill`) are generated by the
templates and are not listed here. For a library not listed, the generated `/add-library-skill`
decides whether the package needs a skill at all, searches skills.sh (`npx skills find`) and the
web, vets the candidate, and installs it without asking.

UI-enabled projects already ship the optional `design-taste` visual planning skill with a
local, on-demand Taste Standard reference. It needs no separate install and does not replace
approved design tokens.

## How to install

Prefer the upstream source through the skills CLI, which records a pin in `skills-lock.json`:

```bash
npx skills add <owner/repo>          # interactive: pick skills, target .agents/skills
npx skills --help                    # confirm current flags before scripting it
```

The CLI's flags change; check `--help` rather than trusting this file.

Skills whose source is **local** are not published upstream: copy the skill directory from an
existing project's `.agents/skills/<name>` or your own skill collection (ask the user where it
lives). **Local (project-adapted)** copies mention another project's names, paths, and package
scope — search the copy for them and rewrite each to this project's before using it.

When Claude Code is used, symlink each into `.claude/skills/` (the scaffold script does this for skills
present at render time; for later installs:
`ln -s ../../.agents/skills/<name> .claude/skills/<name>`), add a bullet to `.agents/README.md`,
a row to `context/library-docs.md`, and regenerate the catalog with
`<runtime> scripts/skills/index.mjs` (docs-check fails until you do).

Install only what the confirmed stack uses. A skill for a library you do not use is noise that
agents will still load.

## MCP servers worth wiring

Use the active harness’s MCP configuration (`.mcp.json` for Claude Code, `.codex/config.toml`
for Codex). Do not assume one harness reads another’s configuration.

| Server | When |
| --- | --- |
| `next-devtools` (`npx -y next-devtools-mcp@latest`) | Next.js — routes, errors, logs from the running dev server |
| `shadcn` (`npx shadcn@latest mcp`) | shadcn registry |
| Analytics/observability vendor MCP (e.g. PostHog) | When that vendor is in the stack |
